# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [0.0.4] - 2026-11-07

### Security

- **The hashed tool locks carry no known-vulnerable version.** The
  locks in `requirements/` were regenerated (releases up to 2026-10-24)
  and now resolve for Python 3.11 and later. That clears the 105
  Dependabot alerts they raised, among them certifi (critical),
  urllib3, cryptography, dulwich, filelock, msgpack, pip, poetry and
  requests. Most fixed releases dropped Python 3.9 and 3.10, both
  end-of-life, so the old locks pinned vulnerable versions for them.
- **Breaking**: a caller that runs `python-ci.yml` (pip or poetry),
  `security.yml`'s Python audit or `docs.yml` on Python 3.9 or 3.10 can
  no longer install the hashed tools; move to 3.11 or later (the
  `python-versions` default is already `["3.11", "3.12"]`).

### Changed

- **Actions updated (Dependabot #19, 34 updates)**, most to Node 24:
  checkout 7.0.1, setup-python/setup-node 7.1.0, setup-go 7.0.0,
  setup-uv 10.3.2, upload-artifact 7.0.2, download-artifact 8.0.2,
  upload-pages-artifact 5.0.0, deploy-pages 5.0.1, codeql-action
  4.39.1, codecov 7.1.1, the docker actions, cosign-installer 4.1.2,
  action-gh-release 3.0.3, pnpm/action-setup 6.1.0. Every version
  comment now names the exact release its SHA points at.
- **Self-hosted runners need 2.327.1 or later** for the Node 24
  actions; a caller passing an older `runner` fails.
- `release.yml`: the Rust toolchain steps pass `toolchain: stable`,
  which dtolnay/rust-toolchain's master requires.
- `node-ci.yml` and `release.yml`: when `package.json` declares pnpm
  in `packageManager`, that version is used and `pnpm-version` is
  ignored; pnpm/action-setup 4 and later fail when the two differ.
- Container signing installs cosign 3, which stores signatures in the
  OCI 1.1 bundle format; verify with cosign 3.
- **Every `pip install` in the workflows is hash-pinned.** The Python
  tools (ruff, mypy, poetry with poetry-plugin-export, pip-audit, bandit,
  MkDocs, Sphinx, yamllint) install with `pip --require-hashes` from
  locks in `requirements/`, generated by `uv pip compile --universal
  --generate-hashes` from releases at least 14 days old. The reusable
  workflows fetch the locks at their own commit (`job.workflow_sha`), so
  a caller that pins a workflow by SHA pins its tools too. This clears
  the 15 Scorecard Pinned-Dependencies alerts.
- **Breaking, `python-ci.yml` with `package-manager: pip`**: the project
  installs as `pip install --require-hashes -r <requirements-file>`
  then `pip install --no-deps -e .`, instead of `pip install -e
  ".[dev]"`. The new `requirements-file` input (default
  `requirements-dev.txt`) names a hashed lock; generate it with `uv pip
  compile pyproject.toml --extra dev --universal --generate-hashes -o
  requirements-dev.txt`. The job fails with that hint when the file is
  missing.
- **Breaking, `python-ci.yml` with pip or poetry**: `ruff-version`, and
  `mypy-version` for pip, accept only the hash-pinned version (the
  default). Any other value, including `''`, still works with
  `package-manager: uv`.
- **Breaking, `docs.yml` for MkDocs and Sphinx**: a caller's
  `requirements-docs.txt` or `docs/requirements.txt` must carry hashes,
  since it installs with `--require-hashes`.

### Fixed

- **`rust-ci.yml` coverage installs cargo-tarpaulin 0.37.5.** The
  unpinned install resolved to 0.35.2, whose profile parser rejects the
  LLVM 23 profiles written by rustc 1.99 ("consistency check for reading
  counts failed"), so callers using tarpaulin's LLVM engine
  (staticweaver) failed with "No coverable lines found".
- `security.yml`: the Python audit of a Poetry project ran `poetry
  export`, which Poetry 2 moved to a plugin, so the step failed with
  "The requested command export does not exist". The poetry lock now
  includes poetry-plugin-export.

### Added

- `.github/dependabot.yml`: weekly updates for the SHA-pinned actions and
  the `requirements/` locks, each held back 14 days by `cooldown`.
- `codeql.yml`: CodeQL analysis of the workflows (the `actions`
  language) on every pull request, on main and weekly.
- `tests/validate.sh`: fails on a `pip install` without
  `--require-hashes`, on a lock a workflow fetches but `requirements/`
  lacks, and on a `ruff-version` or `mypy-version` default that differs
  from its lock.

## [0.0.3] - 2026-10-26

### Fixed

- **`rust-ci.yml` and `docs.yml` now build on the toolchain the caller
  asks for.** `dtolnay/rust-toolchain` only runs `rustup default`, and a
  caller's `rust-toolchain.toml` beats that, so a repo pinning `stable`
  there ran its MSRV and nightly jobs on stable while they reported green
  (staticdatagen's `msrv` job built with 1.99.0 while asking for 1.88.0).
  Every job that installs `inputs.rust-version` now exports
  `RUSTUP_TOOLCHAIN`, which beats the file, and fails unless `rustc` in
  use is the requested version. `tests/validate.sh` checks that every such
  install is pinned and verified.
- `release.yml`: the checkout stays clean so `cargo publish` can run (#7).
- `node-ci.yml`: test arguments reach pnpm's test script after a `--`
  separator (#5).
- `security.yml`: dependency review uses `moderate`, the value the action
  accepts, instead of `medium` (8b4bfb5).
- `rust-ci.yml` coverage: package exclusion passes `--exclude` with
  `--workspace`, and tarpaulin arguments are a bash array, so globs and
  word splitting no longer break them (738590a, 1301362, 99a39f7).

### Added

- `rust-ci.yml`: a `coverage-exclude-packages` input that leaves packages
  out of coverage (2d0f335, renamed in ee4d1cf).
- `security.yml`: an `allow-ghsas` input for the dependency-review job
  (4777ab1).
- `release.yml`: SBOMs for Python and Node are uploaded instead of
  discarded (#8), cross linkers are installed for the Linux targets (#9),
  and Rust crates publish through crates.io trusted publishing (#10).
- `node-ci.yml`: callers can opt into the `packageManager` field for pnpm
  (#12).

### Changed

- Callers whose `rust-toolchain.toml` pins `stable` now get real nightly
  rustdoc builds from `docs.yml` (its default `rust-version` is
  `nightly`), as the input always promised.
- `rust-ci.yml`: the audit job installs a prebuilt `cargo-audit` instead of
  compiling it on every run (#11).
- `python-ci.yml`: ruff and mypy versions are pinned (#6).
- This repository's own Validate workflow runs on every pull request, not
  only on workflow changes: it is a required check, so a docs-only PR
  could never merge.
- `scorecard.yml`: ossf/scorecard-action 2.5.0. 2.4.0 pulled its image
  from gcr.io, which now refuses the pull, so every Scorecard run failed.
- `go-ci.yml`, `security.yml` and `validate.yml` install staticcheck
  v0.8.2, govulncheck v1.9.0 and actionlint v1.7.12 instead of `@latest`,
  so a new tool release cannot change a caller's result overnight.
- Actions: Swatinem/rust-cache 2.9.1 (#2), setup-go and setup-node 6.4.0
  on Node 24 (#3), codecov-action 7.0.0 (#4).

## [0.0.2] - 2026-04-04

### Added

- **Go CI workflow** (`go-ci.yml`): vet, staticcheck, test, coverage, cross-platform
- **Go security audit** in `security.yml` using govulncheck
- **Go release** in `release.yml` with cross-compilation support
- **SLSA Build Level 3** attestations on all release artifacts via `actions/attest-build-provenance`
- **Sigstore container signing** in `docker.yml` via cosign (keyless OIDC)
- **Trusted Publishing** for PyPI (`pypa/gh-action-pypi-publish` with OIDC)
- **npm provenance** via `--provenance` flag on publish
- **SBOM generation** (SPDX) for all release languages, not just Docker
- **OpenSSF Scorecard** workflow (`scorecard.yml`) for self-assessment
- **ARM64 runner support** via `runner` input on all CI and security workflows
- `SECURITY.md` — vulnerability reporting and security policy
- `CHANGELOG.md` — this file
- `CONTRIBUTING.md` — contribution guide
- `examples/` — complete caller workflow examples for all languages

### Changed

- **All actions pinned by commit SHA** — no more mutable `@v4`/`@v5` tags (supply chain hardening post-CVE-2025-30066)
- **Top-level `permissions: {}`** on every workflow with granular job-level overrides (principle of least privilege)
- Python CI default package manager changed to `uv`
- Node.js default version updated to 22
- Python default version updated to 3.12
- `taiki-e/install-action` uses `@v2` with explicit `tool:` input instead of tool-specific tags

### Security

- All 34 GitHub Actions pinned by full SHA — prevents tag-mutation supply chain attacks
- Added `persist-credentials: false` to all checkouts — tokens not stored in git config
- Added `id-token: write` permissions for OIDC/Sigstore flows
- Removed `safety` from Python audit (deprecated, replaced by `pip-audit`)
